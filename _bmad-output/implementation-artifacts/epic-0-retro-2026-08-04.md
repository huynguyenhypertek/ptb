## Challenges

### 1. Copy-and-Simplify Carries Bugs
**Most critical finding of the epic.** In E0-S3, `SequentialNumberService.PeekNextNumber()` was returning the **last-assigned** number instead of the **next** number. This was a bug in the ORIGINAL `PhotoBooth.UI` source code that was blindly copied.

> [!IMPORTANT]
> `copy_and_simplify` ≠ `copy_and_trust`. Copied code must be reviewed as critically as new code.

### 2. High Finding Count Per Story
Average 6 findings per story (30 total across 5 stories). While all were caught in review, this suggests initial implementations could benefit from more careful self-review before submission.

### 3. Input Validation Gaps in Copied Code
E0-S4: `--planType=` and `--apiBaseUrl=` accepted empty values, which would silently kill HTTP connectivity. These gaps existed in the UI source code and were faithfully copied.

### 4. Dispose Pattern Inconsistency
E0-S5: Initial implementation had non-idempotent `Dispose()` and a lambda PropertyChanged handler that couldn't be unsubscribed. These are patterns that should be established as standards from day 1, not discovered in review.

---

## Key Insights

1. **`copy_and_simplify` ≠ `copy_and_trust`** — The PeekNextNumber bug (E0-S3 H1) and empty-value guard gaps (E0-S4 M1/M2) prove that source code is NOT always correct. Every copied method must be reviewed for logic correctness.

2. **Code review is the quality gate** — 30 findings, 100% caught in review. The adversarial review process is effective and should continue.

3. **Type tightening improves safety** — The `ObservableObject` → `ViewModelBase` constraint change prevented potential runtime failures. Always use the tightest type constraint possible.

4. **Defensive patterns from day 1** — Idempotent Dispose (`_disposed` guard + `GC.SuppressFinalize`), named event handlers (not lambdas) for proper unsubscribe, and empty-value guards should be default patterns.

5. **Vietnamese → English comment translation** — Recurring finding across stories. All comments should be in English for the Event codebase.
